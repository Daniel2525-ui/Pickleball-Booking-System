# Open Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Staff run weekly open play sessions; players book and pay for 1–4 spots online (card or GCash) or as walk-ups, with the same cancellation and refund rules as court bookings.

**Architecture:** Two new tables (`open_play_schedules`, `open_play_sessions`). Each created session inserts one **block row** per court into `bookings`, with the court set, `open_play_session_id` set, `open_play_spots` NULL and status `confirmed`. The existing exclusion constraint `no_overlapping_active_court_bookings` then blocks court bookings atomically, with no change to court hold code. A **spot booking** is a `bookings` row with `court_id` NULL, `open_play_session_id` set and `open_play_spots` 1–4, plus a normal `payments` row and its own `basket_id`. That way Stripe checkout, reconciliation, GCash proof and verify, the cancel route, the refund ledger and Refund Owed all carry it, with targeted branches only where they assume a court. Capacity is enforced in SQL under a `FOR UPDATE` lock on the session row.

**Tech Stack:** Next.js 16 (read `node_modules/next/dist/docs/` before writing Next code), Supabase Postgres (SQL functions, RLS), Stripe Checkout (card), existing GCash manual flow, `node --test` unit tests, the Docker Postgres integration runner (`npm run test:integration`), Playwright e2e on the local stack.

**Spec:** `docs/superpowers/specs/2026-11-02-open-play-design.md`

## Global Constraints

- **Max spots per booking** is 4, and **max per player per session** is 4 across all of that player's active spot bookings.
- **Sessions** are generated for today through today + 27 days (Asia/Manila), rolling, by the existing 15-minute cron and on every schedule save.
- **Customer cancellation:** full refund if cancelled 2+ hours before start (the existing `CANCELLATION_CUTOFF_HOURS = 2`, unchanged). Staff cancellation always refunds in full, at any time.
- **Refunds:** card refunds go through `reserve_payment_refund` and `processPendingRefundJobs`. GCash and cash refunds go through Refund Owed (a paid payment on a cancelled booking), unchanged.
- **Before staff can cancel a session,** every GCash payment in it that is awaiting verification (`hold_expires_at = 'infinity'`) must be approved or rejected.
- **Display copy:**
  - Players page title: "Open Play".
  - Card subtitle: "All levels welcome".
  - Grid cell label: "Open play".
  - Booking title: `Open play · N spot(s)`.
  - Block rows in admin: "Open play (court reserved)".
- **No new npm dependencies.**
- **Server-side enforcement:** all money and capacity rules live in SQL functions or route handlers, never only in the browser.
- **Testing:** write e2e runs on :3200 against local Supabase only (`.env.local` is production). The migration is applied to production only after the owner says so.
- **Migrations:** new files under `supabase/migrations/` named `20261103NNNNNN_open_play_*.sql`. When redefining an existing function, start from `pg_get_functiondef` on the **local** database and change only the branches named here.

## Review Focus

1. **Two players race for the last spot** at the same moment: exactly one hold succeeds, and the other gets `SESSION_FULL`. Test in Task 3.
2. **A player pays late for a hold that expired** while someone else took the spot: the late payment is refunded, not confirmed over capacity. Test in Task 3 (reconcile over capacity).
3. **A player books from a stale page** after the session was cancelled or filled: the hold is refused, including through the resume-payment path (`confirm_checkout_hold`). Test in Task 3.
4. **A flagged date's clashing court booking is cancelled:** the next generator run creates the session. A court booking made while the session exists is refused. Test in Task 2.
5. **Staff cancel a session with a card hold still at Stripe:** the booking is cancelled, and a later payment is refunded by the existing cancelled-booking branch. Test in Task 4.

Schema (exact):
- **`open_play_schedules`:**
  - `id uuid pk default gen_random_uuid()`
  - `day_of_week text NOT NULL` (CHECK it is one of the 7 names used by `operating_hours.day_of_week`)
  - `start_time time NOT NULL`, `end_time time NOT NULL`, with CHECK `end_time > start_time`, both whole hours
  - `court_ids uuid[] NOT NULL`, CHECK `cardinality >= 1`
  - `capacity int NOT NULL`, CHECK `> 0`
  - `price_per_spot numeric(10,2) NOT NULL`, CHECK `> 0`
  - `active boolean NOT NULL default true`, `created_at timestamptz NOT NULL default now()`
- **`open_play_sessions`:**
  - `id uuid pk`, `schedule_id uuid NOT NULL REFERENCES open_play_schedules ON DELETE RESTRICT`
  - `session_date date NOT NULL`, `start_time`, `end_time`, `court_ids uuid[]`, `capacity`, `price_per_spot`, all copied from the schedule at creation
  - `status text NOT NULL` CHECK `IN ('open','cancelled','flagged')`
  - `flag_reason text`, `created_at`
  - `UNIQUE (schedule_id, session_date)`
- **`bookings` changes:**
  - Add `open_play_session_id uuid REFERENCES open_play_sessions ON DELETE RESTRICT` and `open_play_spots smallint`.
  - `ALTER court_id DROP NOT NULL`.
  - Add CHECK `bookings_court_or_open_play`: `(court_id IS NOT NULL AND open_play_spots IS NULL) OR (court_id IS NULL AND open_play_session_id IS NOT NULL AND open_play_spots BETWEEN 1 AND 4)`.
  - Replace `bookings_customer_identity_check` with the old expression `OR (open_play_session_id IS NOT NULL AND open_play_spots IS NULL AND user_id IS NULL AND customer_id IS NULL)`. That lets block rows have no owner.
  - Add a partial index on `(open_play_session_id) WHERE open_play_session_id IS NOT NULL`.
- **Active spot rule** (both helpers): rows with `open_play_session_id = p_session_id AND court_id IS NULL AND (status IN ('confirmed','checked_in','in_progress','completed') OR (status = 'pending' AND public.hold_release_after(hold_expires_at, created_at) > clock_timestamp()))`. `infinity` holds count, because `hold_release_after` returns infinity for them. `open_play_spots_taken` sums `open_play_spots` excluding `p_exclude_booking`. `open_play_player_spots` sums the same filtered by `user_id = p_user_id OR customer_id = p_customer_id`.
- **RLS:** enable on both tables. Admin (`public.is_admin()`) gets full access, and nobody else gets direct access (customers read through the Task 5 RPC). Helpers are `SECURITY DEFINER SET search_path = ''`, `GRANT EXECUTE` to `authenticated, service_role`.

### Task 3: Holding spots, checkout and payment reconciliation

**Files:**
- Create: `supabase/migrations/20261103000003_open_play_booking.sql`
- Modify: `tests/integration/run-pg-integration.mjs`

**Interfaces:**
- Consumes: Task 1 helpers; existing `hold_release_after`, `reserve_payment_refund`.
- Produces:
  - `public.hold_open_play_spots(p_session_id uuid, p_spots int, p_payment_method text DEFAULT 'stripe') RETURNS jsonb`, returning `{basket_id, booking_id, payment_id, amount, hold_expires_at}`:
    - The caller must be `authenticated`. It uses `auth.uid()` and never a parameter.
    - It locks the session row `FOR UPDATE`.
    - It raises: `NOT_FOUND`; `SESSION_UNAVAILABLE` (status not `open`, or start time already passed in Manila); `INVALID_ARGUMENT` (spots not 1–4, or method not `stripe`/`gcash`); `SESSION_FULL` (taken + spots > capacity); `PLAYER_LIMIT` (`open_play_player_spots` + spots > 4).
    - Before counting, it cancels this session's stale spot holds (pending and `hold_release_after <= now`). They get `cancel_reason 'expired'`, and their pending payments become `failed`.
    - It inserts a spot row: `status 'pending'`, `basket_id gen_random_uuid()`, `customer_name` from `profiles.full_name`, `total_amount = spots × price_per_spot`, `hold_expires_at = now() + 35 minutes`. It also inserts a payment: `pending`, with `payment_method = p_payment_method` and `currency 'php'`.
  - `confirm_checkout_hold` (redefined): when the booking's `court_id IS NULL`, it replaces steps 4–5 (court lock and overlap check). Instead it locks the session `FOR UPDATE`, raises `SESSION_UNAVAILABLE` unless the status is `open`, and raises `SESSION_FULL` if `open_play_spots_taken(session, p_booking_id) + own spots > capacity`. Everything else is unchanged.
  - `reconcile_booking_payment` (redefined): for spot rows (`court_id IS NULL`):
    - **Branch 2:** checks the session instead of the court. If the session is not `open`, it does the same refund with `cancel_reason 'court_unavailable'` and reason `COURT_UNAVAILABLE`.
    - **Branch 5:** checks `open_play_spots_taken(session, p_booking_id) + own spots > capacity` instead of court overlap. If over, it does the same refund with `slot_conflict`.
    - Other branches are unchanged.
